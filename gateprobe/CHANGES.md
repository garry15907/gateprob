# gateprobe 변경 내역 (0.4.0까지는 gwcheck)

(안에 적힌 `plan/`, `live_evidence/` 경로는 팀 내부 기록이라 이 저장소에는 없다)

## 0.6.0 (2026-11-25)

- 정상 확인 화면에 "GitHub에 올리기" 버튼 추가 (사용자 요청). 저장 뒤 누르면 새 브랜치 만들기, 저장한 파일 하나만 커밋, push를 대신 하고
  제목과 본문이 채워진 PR 만들기 페이지를 연다. 서버는 화면이 보낸 명령이 아니라 저장할 때 만든 계획만 실행한다.
  main 직접 push, 강제 push는 하지 않는다
- 완성본 독립 검토 3건(보안, 경계 사례, 처음 쓰는 사람) 반영
  - 저장한 뒤 파일이 바뀌었으면 거부(저장 때 쓴 내용의 해시와 비교). git 사용자 이름이 없으면 아무것도 바꾸기 전에 거부하고 안내
  - 파일 이름을 글자 그대로 다룸(`--literal-pathspecs`). 전에는 `s[1].json`을 올릴 때 `s1.json`의 수정이 딸려 갈 수 있었다
  - push는 입력을 막고 출력을 임시 파일로 받으며, 시간이 넘으면 자식 프로세스(로그인 도우미, ssh)까지 끝낸다. 잠금 밖에서 실행
  - 단계마다 시간 초과를 처리. 커밋 전이면 되돌리고(끝낸 git이 남긴 index.lock도 정리), 커밋 뒤면 이어서 할 명령과 돌아가는 명령을 보여 줌
  - 되돌리기가 성공했는지 확인하고, 올려 둔(staged) 파일도 내림. 저장에 실패하면 앞 저장의 올리기 계획을 버림
  - 복사용 명령의 경로는 허용한 글자만 받음(PowerShell은 “ ”도 따옴표로 읽는다)
  - 저장 전 사본(.bak)을 저장소 안이 아니라 `.git/gateprobe-backup/`에 둠
  - 기본 브랜치가 아닌 브랜치, 앞서 올린 정상 확인 브랜치에서 저장하면 경고
  - 주의할 점을 버튼 위와 확인 창에 보여 주고, 올린 뒤 새 브랜치에 남아 있다는 것과 돌아가는 명령을 눈에 띄게 표시. 서버 문구를 합니다체로,
    사용자에게 시키는 말은 "~하세요"로 통일. 말 풀이에 브랜치, 커밋, 올리기 추가
- 명령 네 줄은 "직접 하려면" 아래로 옮김. 올린 뒤에는 숨김

## 0.5.1 (2026-11-25)

- `observe`가 사전 객체(fixtures)를 올리지 않던 것을 고침. run과 같이 시나리오마다 먼저 올리고 같은 `{ns}`로 읽는다.
  전에는 사전 객체를 읽는 단계가 실패한 상태의 결과가 '지금 결과'로 적힐 수 있었다 (실제 확인 준비 중 발견).
  올리지 못하면 그 시나리오는 호출하지 않고 '호출 안 함 (사전 객체를 올리지 못함: …)'으로 적는다
- 정상 확인 화면: '호출 안 함'으로 잠근 단계에 observe가 적은 이유를 그대로 보여 줌. 커밋 안 된 수정 때문에 남긴 .bak의 이유를 바르게 표시

## 0.5.0 (2026-11-24)

- 이름을 gwcheck에서 gateprobe로 바꿈. 명령 `gateprobe`, 모듈 `python -m gateprobe`. 옛 명령 `gwcheck`도 같은 프로그램으로 남김.
  새로 `init`하면 변수 파일은 `.gateprobe_vars.json`. 기존 대상 파일은 `vars_file`에 적힌 이름을 그대로 읽는다.
  환경 변수는 `GATEPROBE_STEP_SUMMARY`(옛 이름 `GWCHECK_STEP_SUMMARY`도 받음)
- 정상 확인 화면: 완성본 독립 검토 3건 반영 (`plan/검토결과_정상확인화면_2026-11-24.md`)
  - 지금 결과가 도구 오류·판정 불가인 단계는 잠그고 이유 표시
  - 화면을 연 뒤 원본이 바뀌었으면 저장 거부. 커밋 안 된 수정이 있으면 `.bak`과 경고
  - 저장·읽기 동시 요청은 잠금으로 순서를 지키고, Windows에서 교체가 잠깐 막히면 다시 시도. 쓴 뒤 fsync
  - 올릴 명령은 `cd` 대신 `git -C "<저장소>"`, 브랜치 이름도 따옴표. 경로에 `"`, `$`, `` ` ``가 있으면 명령을 만들지 않음. 한글 id 유지, 긴 메시지는 id 경계에서 자름
  - 안내에 순서 세 줄, 용어 풀이(validate, PR, CI), 비교 문구를 "참고"로 낮추고 "같음" 개수는 뺌, 저장 뒤 진행 줄, 화면 읽기 프로그램용 묶음 이름과 알림
  - 단계 소제목을 "2단계 정상"에서 "2단계: 이 호출은 어떻게 되어야 하나요?"로 ("문제없다"로 읽힌다는 지적. 낱말 "정상"은 안내와 결과서에 그대로)
- `init`이 `.gitignore`에 `*_observed.json`도 넣는다
- 시험: `python -m gateprobe.test_gateprobe`(36개), `python -m gateprobe.test_ui`(묶음 11개)

## 0.4.0 (2026-11-24)

정상 확인 화면. 계획과 독립 검토 3건: `plan/정상확인화면_계획_2026-11-24.md`, `plan/검토결과_정상확인화면_2026-11-24.md`

- `gwcheck ui`: observe 초안의 지금 결과를 보며 단계마다 정상(허용 / 차단 / 기록만, 차단 위치)을 고르는 로컬 웹 화면. 정상 칸은 미리 채우지 않는다
  - 저장은 원본에서 고른 단계의 `expect`만 바꾸고 원본의 들여쓰기·줄바꿈을 따른다. observe 뒤에 원본이 바뀌었으면 저장하지 않는다
  - 고른 정상과 지금 결과를 실행기와 같은 판정으로 비교해 참고로 보여 준다
  - git 저장소 안의 파일이면 GitHub에 올릴 명령과 PR 주소를 보여 준다 (실행하지는 않는다)
  - 127.0.0.1 전용, 실행마다 토큰, Host·Origin 검사, nonce CSP, 파일 내용은 textContent로만
- `observe`와 `init`의 다음 단계 안내에 `gwcheck ui`
- 시험: `python -m gwcheck.test_ui` (묶음 10개)

## 0.3.1 (2026-11-23)

비밀값 등록·CI 시연 전 검토 4건(독립 검토 3건, 외부 검토 1건)을 반영. 근거: `plan/검토결과_전체_2026-11-23.md`

- 판정 낱말을 한 벌로: 종합 판정 적합/부적합/점검 미완료, 항목 판정 일치/불일치/확인 필요/기록만, 정상·결과 칸은 차단/허용.
  터미널 실행 줄(`[일치] … 정상 허용, 결과 차단`)과 마지막 결론 줄, CI 마크다운 요약 첫 줄이 HTML 결과서 첫 줄과 같은 문장
- `observe`: 호출 전에 저장 파일 충돌과 TODO 개수를 확인하고, TODO가 없으면 호출하지 않는다. 보낼 도구와 횟수를 먼저 보여 준다.
  TODO가 없는 시나리오, 마지막 TODO 뒤 단계는 보내지 않는다. 초안은 `"expect": "TODO"` 그대로 두고 `"지금결과"`를 따로 적는다
- `doctor`: 마지막 줄에 실패·주의 개수와 정책 엔진 모드. LOG_ONLY가 '문제 없음'에 묻히지 않는다. boto3가 없으면 설치 방법 안내
- `validate`: 기대값 오타에 가까운 값 제안("ALOW" → "ALLOW"를 뜻하나요?), 같은 오류는 한 줄로 묶음
- 결과서 접근성: 표 머리글 scope와 표 제목, 인쇄 때 호출 흐름 펼침, 회색 대비 7:1, 최소 12px, 좁은 화면에서 표만 가로 스크롤, 흐름의 불일치를 글자로도
- 사전 준비 실패 예외 문구의 계정 ID를 결과서에서 가림
- 도움말 한국어화(명령은 쓰는 순서대로, 모든 옵션에 설명)
- README: 준비물, 순서를 init 안내와 같게, PowerShell 환경 변수 예시, 한글 콘솔 안내, 용어 풀이, 오프라인 키트와 도구 구분

## 0.3.0 (2026-11-23)

AWS 공개 예제 Gateway 2개(Terraform 웹 검색, 시간 정책 은행 비서)에 적용하면서 고친 것과 편의 기능.
근거: `live_evidence/EXT_SAMPLES_RESULT_2026-11-23.md`

고친 것
- MCP 버전: 대상 파일 `mcp_version`("2026-07-28" 기본, "2025-11-25")으로 고른다. `init`이 Gateway 설정의 지원 버전을 읽어 적는다.
  0.2.0은 2025-11-25만 받는 Gateway에서 HTTP 400으로 점검을 시작하지 못했다(통과로 보고하지는 않음)
- 버전 거부, 입구 인증 실패(401·403), 주소 없음(404)에 고칠 방법을 한 줄로 붙인다
- 도구 오류로 분류된 호출의 응답 문구를 기록과 결과서에 남긴다(업무 오류와 인프라 오류를 사람이 가릴 수 있게)
- 자격 증명·토큰 환경 변수가 없을 때 추적 정보 대신 한 줄 안내와 종료 코드 3
- 결과서 응답 칸에서 뜻 없는 HTTP 200 표기를 뺐다

새 기능
- JWT Gateway 토큰 자동 발급: `auth.type = "oauth"`. `init`이 OIDC 설정에서 토큰 주소를 찾아 적고, 클라이언트 ID·비밀값 환경 변수만 넣으면 gwcheck가 토큰을 받고 만료 전에 다시 받는다
- `gwcheck doctor`: 실행 전 진단(대상 파일, 자격 증명·토큰, 접속, MCP 버전, 정책 엔진 모드)
- `gwcheck observe --execute`: 기대값 TODO 옆에 '지금 결과'를 적은 초안 시나리오를 새 파일로 만든다(TODO는 남겨 사람이 확인해야 실행된다)
- `init`이 도구 입력 스키마로 숫자·선택지·기본값 인자를 예시로 채우고, 문자열 인자에는 설명을 붙인 TODO를 남긴다. 정책 엔진이 ENFORCE면 막힌 도구가 목록에서 빠질 수 있다고 알린다
- 단계별 `wait`(초): 앞 호출 기록이 정책 엔진에 보이기까지, 또는 "5분 뒤" 같은 시간 조건을 위해 기다린다

알려진 한계
- 2025-11-25만 받으면서 세션(initialize, Mcp-Session-Id)을 요구하는 Gateway는 아직 지원하지 않는다
- Gateway 입구 인증 실패는 별도 분류 없이 판정 불가(UNKNOWN)로 처리한다
